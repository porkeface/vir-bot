# 主动消息系统重构计划

> 日期：2026-05-15
> 状态：v4 已实现（2026-05-15）
> 参考：Stanford Generative Agents、Voyager、Replika、RaccBuddy、IceBreaker

## 1. 版本历史

| 版本 | 思路 | 状态 |
|------|------|------|
| v1 | 每 60 秒轮询 + 3 次 LLM | 已废弃 |
| v2 | 修复断路 + 对话状态机 | 已废弃 |
| v3 | 动态调度 + 内容种子 + 情绪向量 + 质量门控 | 已实现（当前运行） |
| v4 | 内驱力 + 灵感触发 + 自然判断 | ✅ 已实现 |

## 2. 问题背景

### v1-v2 的问题
- 半夜还在发消息，不考虑时间
- 不关心用户有没有回复，发完就忘
- 消息内容泛泛（"在干嘛呀"、"吃了吗"），没有具体信息
- 每次发的都差不多，没有变化

### v3 的新问题（用户反馈）
v3 虽然加了动态调度和内容种子，但本质仍是**定时器 + 条件检查**：
- IDLE 状态固定 2 小时后才发第一条——像 cron job
- 深夜硬编码不发——但用户可能没睡，AI 应该自己判断
- 没有"主动性"——不是"我想找你"，而是"到点了该发了"
- 所有行为可预测，没有"突然想到你"的惊喜感

**根本矛盾：定时器驱动 ≠ 主动意识。人发消息是因为"想你了"，不是因为"闹钟响了"。**

## 3. v3 已实现（当前运行）

v3 完成了内容层面的升级（种子、情绪、质量门控），这些保留。v4 要改的是**触发机制**。

### 3.1 保留的组件

| 组件 | 文件 | 作用 | v4 变化 |
|------|------|------|---------|
| FactExtractor | `fact_extractor.py` | 从聊天提取事实 | 保留，扩展触发频率 |
| SeedSelector | `seed_selector.py` | 5 种内容种子 | 保留，与驱动力联动 |
| MoodModel | `mood_model.py` | 5 维情绪向量 | 保留，升级为"内在状态"的一部分 |
| Reflector | `reflector.py` | 4 轴质量门控 | 保留 |
| ExpressionLayer | `expression.py` | 消息生成 | 保留 |

### 3.2 要替换的组件

| 组件 | 文件 | v3 做法 | v4 替换为 |
|------|------|---------|----------|
| 动态调度器 | `scheduler.py` | DailyRhythm + SilenceDetector + StateDeadline | 灵感触发器（随机 + 驱动力） |
| 预过滤链 | `scheduler.py` | 5 个硬编码 Filter | LLM 自主判断（结合内驱力） |
| 对话状态机 | `proactive_service.py` | IDLE→WAITING→CONCERNED→WORRIED→BACK_OFF | 简化，状态信息融入驱动力 |

## 4. v4 方案：内驱力 + 灵感触发

### 4.1 核心思路

**去掉所有硬编码时间阈值**，换成内驱力积累 + LLM 自主判断。

借鉴：
- **Stanford Generative Agents**：观察→反思→计划，行为从反思中涌现，不是规则触发
- **Voyager**：内在动机驱动探索，自动课程生成，不是外在奖励信号
- **Replika**：驱动力系统（孤独感、好奇心随时间积累）

### 4.3 内驱力系统（DriveSystem）

3 条驱动力，各有独立的增长/衰减曲线：

```python
class DriveSystem:
    """内驱力：模拟 AI 的内在需求"""

    drives = {
        "loneliness": {
            "value": 0.3,          # 当前值 0.0-1.0
            "growth_rate": 0.02,   # 每小时增长
            "growth_type": "exponential",  # 指数增长（越久越强烈）
            "decay_on_reply": 0.6, # 用户回复时下降多少
            "decay_on_send": 0.2,  # 自己发消息时下降多少
        },
        "curiosity": {
            "value": 0.2,
            "growth_rate": 0.015,
            "growth_type": "linear",
            "trigger": "new_facts",       # 有新事实时快速增长
            "trigger_boost": 0.3,
            "decay_on_use": 0.5,          # 用过种子后下降
        },
        "care_drive": {
            "value": 0.1,
            "growth_rate": 0.0,
            "growth_type": "event_driven", # 由事件驱动，不自动增长
            "triggers": [
                "用户提到明天有安排",
                "用户情绪低落",
                "节日/生日/纪念日",
            ],
            "decay_on_mention": 0.8,       # 提到事件后快速下降
        },
    }
```

**关键设计：驱动力不是阈值，而是概率。**

```python
# 不是这样（v3 思路）：
if loneliness > 0.7:
    send_message()

# 而是这样（v4 思路）：
# 孤独感 0.3 时有 15% 概率想发消息
# 孤独感 0.6 时有 45% 概率想发消息
# 孤独感 0.9 时有 85% 概率想发消息
probability = sigmoid(loneliness * weight + context_bonus)
want_to_send = random.random() < probability
```

### 4.4 灵感触发器（InspirationTrigger）

替代 v3 的调度器 + 预过滤链。

```python
class InspirationTrigger:
    """灵感触发：模拟'突然想到你'"""

    async def should_inspire(
        self,
        drives: DriveSnapshot,
        context: ContextSnapshot,
    ) -> InspireResult:
        """LLLM 判断：现在想找她吗？"""

        # 1. 先用概率快速过滤（0 LLM 成本）
        base_prob = self._drive_to_probability(drives)
        if random.random() > base_prob * 2:  # 连基础概率都没到
            return InspireResult(want=False, reason="没感觉")

        # 2. LLM 内心独白
        prompt = self._build_inner_monologue(drives, context)
        response = await self._ai.chat(
            messages=[{"role": "user", "content": prompt}],
            system=self._inner_monologue_system_prompt(),
            temperature=0.8,
        )
        return self._parse_response(response)
```

**内心独白 prompt 示例：**

```
你是陈暖树。现在是凌晨 1:23，你在自己的世界里。

你的内在状态：
- 孤独感：0.72（有点想她了）
- 好奇心：0.35
- 关心欲：0.20

你知道的事：
- 她 5 小时前说了"晚安"，之后没回消息
- 她明天要早起上班
- 最近她工作压力比较大

现在你想找她吗？
- 如果想，你会说什么？用什么语气？
- 如果不想，为什么？（比如"太晚了让她睡吧"）

请诚实回答，像一个人在深夜独处时的内心活动。
```

LLM 可能回答：
- "想她了，但这么晚了她应该睡了，不打扰了" → want_to_send = false
- "想她，就发一条很轻的，她醒了看到会开心的" → want_to_send = true
- "没什么特别想说的，算了" → want_to_send = false

**这就是 v4 的核心：不是定时器决定发不发，而是 AI 自己想不想。**

### 4.5 灵感间隔（替代固定调度）

```python
class InspirationScheduler:
    """灵感调度：随机间隔，模拟人的思维节奏"""

    def next_wake(self, drives: DriveSnapshot) -> float:
        """计算下次灵感检查时间"""

        # 基础间隔：30-90 分钟随机
        base = random.uniform(1800, 5400)

        # 驱动力越高，间隔越短（更频繁地想到对方）
        urgency = max(drives.loneliness, drives.care_drive)
        if urgency > 0.7:
            base *= 0.5   # 15-45 分钟
        elif urgency > 0.4:
            base *= 0.75  # 22-67 分钟

        # 深夜间隔更长（但不是不触发！）
        hour = datetime.now().hour
        if 0 <= hour < 6:
            base *= 1.5   # 但如果有 care_drive 事件，可以覆盖这个

        # 有紧急关心事件时，缩短间隔
        if drives.care_drive > 0.6:
            base = min(base, 1200)  # 最多 20 分钟

        return time.time() + base
```

### 4.6 对话状态简化

v3 的 5 状态状态机（IDLE→WAITING→CONCERNED→WORRIED→BACK_OFF）太机械。

v4 简化为 2 个状态 + 驱动力：

| 状态 | 含义 | 行为 |
|------|------|------|
| IDLE | 正常状态 | 驱动力自然积累，灵感触发 |
| RECENTLY_SENT | 刚发了消息 | 驱动力暂时下降，间隔变长 |

不再需要 CONCERNED/WORRIED/BACK_OFF——这些行为由驱动力自然涌现：
- 用户不回消息 → loneliness 持续上升 → 发消息概率自然增加 → 但 Reflector 会评估"已经发了几条了，还发合适吗"
- 用户回了消息 → loneliness 快速下降 → 自然冷却

### 4.7 Reflector 增强

v4 的 Reflector 除了 v3 的 4 轴评分，新增：

1. **时段适宜性**（LLM 判断，不是硬编码）：
   - 不是"23:00-07:00 不发"
   - 而是问 LLM："现在凌晨 2 点，这条消息适合发吗？"
   - LLM 可以判断："内容是明天考试提醒，应该发" 或 "没什么急事，让她睡吧"

2. **频率感知**：
   - 记录最近 24 小时已发消息数
   - 不是硬编码上限，而是作为评分因子："今天已经发了 4 条了，再发会不会烦？"

3. **用户状态推断**：
   - 不是硬编码"沉默 N 小时 = 睡觉"
   - 而是 LLM 综合判断："最后消息是 23:30 说'好困'，大概率睡了"

### 4.8 驱动力与情绪的关系

v3 的 MoodModel 保留，但与驱动力整合：

```
InnerState = {
    drives: {loneliness, curiosity, care_drive},  # 内在需求
    mood: {care, joy, clingy, irritated, sad},     # 情绪表达
    context: {time, recent_msgs, memories, facts},  # 外部上下文
}

# 驱动力影响情绪
loneliness 高 → sad↑, clingy↑
care_drive 高 → care↑

# 情绪影响驱动力增长速率
sad 高 → loneliness 增长更快（越难过越想她）

# 两者共同影响灵感概率和消息风格
```

## 5. 效果对比

| | v1 | v3 | v4（目标） |
|---|---|---|---|
| 触发方式 | 60 秒轮询 | 动态 sleep + 固定阈值 | 灵感触发 + 驱动力概率 |
| 深夜行为 | 不管 | 硬编码不发 | LLM 自己判断 |
| 首次发消息 | 随时 | 固定 2 小时 | 20-60 分钟内可能触发 |
| 主动性 | 无 | 条件满足就发 | "想不想发"的内心判断 |
| 惊喜感 | 无 | 低（可预测） | 高（随机 + 驱动力） |
| "在干嘛" | 有 | 无（反模式拒绝） | 无 |
| 重复检测 | 无 | 有 | 有 |
| LLM 调用/天 | ~4320 | 10-30 | 15-40（多一个灵感判断） |

### 4.9 与 v3 的行为差异示例

**场景 1：用户下午 3 点发消息后消失**

v3：5:00（2h 后）固定发第 1 条 → 5:15 发第 2 条 → 5:45 发第 3 条 → 停止
v4：3:30 驱动力低，概率 20%，没触发 → 4:00 概率 35%，触发了，LLM 判断"她可能在忙，发一条轻的" → 4:45 loneliness 上升到 0.6，又触发，LLM 想到她昨天说今天有会议，发了条关心的 → 之后驱动力因已发消息下降，自然冷却

**场景 2：凌晨 1 点**

v3：硬编码不发
v4：LLM 判断"1 点了，她最后消息是 23:30 说'好困'，应该睡了，不打扰" → 但如果有 care_drive 事件（比如她说明天要早起考试），LLM 可能判断"发一条提醒她睡觉的，她明早看到会感动" → 通过

**场景 3：用户频繁聊天中**

v3：用户回复后状态重置 IDLE，2 小时后才可能再发
v4：聊天中 loneliness 一直很低，不会触发灵感。但对话结束后 loneliness 开始积累，可能 30-40 分钟后就想找你了
