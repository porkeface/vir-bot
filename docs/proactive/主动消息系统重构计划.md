# 主动消息系统重构计划

> 日期：2026-05-15
> 状态：v3 方案设计完成，待实现
> 参考：Sebastian、RaccBuddy、IceBreaker(ACL 2026)、Livia(AIVR 2025)

## 1. 版本历史

| 版本 | 思路 | 状态 |
|------|------|------|
| v1 | 每 60 秒轮询 + 3 次 LLM | 已废弃 |
| v2 | 修复断路 + 对话状态机 | 已实现（当前运行） |
| v3 | 动态调度 + 内容种子 + 情绪向量 + 质量门控 | 设计完成 |

## 2. 问题背景

用户反馈：主动消息像硬编码任务，不是正常人的思维。

具体问题：
- 半夜还在发消息，不考虑时间
- 不关心用户有没有回复，发完就忘
- 消息内容泛泛（"在干嘛呀"、"吃了吗"），没有具体信息
- 每次发的都差不多，没有变化

## 3. v2 已实现（本次改动）

### 3.1 修复用户回复感知断路

`StateTracker.update_from_message()` 和 `RhythmManager.record_interaction()` 写了但从没被调用。现在通过 pipeline 回调串联。

### 3.2 对话状态机

```
IDLE → 发消息 → WAITING → 15min → CONCERNED → 30min → WORRIED → 30min → BACK_OFF
  ↑                                    │                  │                  │
  └──────────── 用户回复 ───────────────┴──────────────────┴──────────────────┘
```

### 3.3 RhythmManager 冷却修复

CONCERNED/WORRIED 状态跳过 RhythmManager 冷却检查，由状态机自己管节奏。

## 4. v3 方案：完整重构

### 4.1 核心思路

把"每 60 秒轮询 + 3 次 LLM"改成"**动态调度 + 内容种子 + 情绪向量 + 质量门控**"。

借鉴：
- **Sebastian**：动态调度、概率化库选择、三层氛围叠加
- **RaccBuddy**：轻量 nudge skill（`should_fire()` 纯数据）+ 4 节点 agentic 图
- **IceBreaker**：从会话摘要蒸馏"触发兴趣"，两步握手

### 4.2 架构总览

```
┌──────────────────────────────────────────────────┐
│              后台任务（每 6 小时）                   │
│                                                    │
│  聊天记录 → FactExtractor → Facts Store           │
│           → InterestDistiller → 兴趣索引            │
└──────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────┐
│              触发层（动态调度器）                     │
│                                                    │
│  DailyRhythm:  早9/午12/晚6/晚9 窗口              │
│  SilenceDetector: 用户沉默 N 分钟 → 触发           │
│  StateDeadline: 状态转移超时 → 触发                 │
│                                                    │
│  next_wake = min(所有源的下次触发时间)               │
│  sleep 到 next_wake 再检查                          │
└──────────────────────────────────────────────────┘
           │ 醒来
           v
┌──────────────────────────────────────────────────┐
│         预过滤层（0 次 LLM，纯数据）                │
│                                                    │
│  DailyLimitFilter:  今日已发 N 条？超了就不发       │
│  CooldownFilter:    距上次发消息够久？               │
│  QuietHoursFilter:  23:00-07:00？不发              │
│  EngagementFilter:  用户没回上一条？冷却翻倍         │
│  ContentFilter:     有新的内容种子可用？没有不发      │
│                                                    │
│  全部通过 → 继续                                    │
│  任何一个不通过 → 跳过，等下次唤醒                    │
└──────────────────────────────────────────────────┘
           │ 全部通过
           v
┌──────────────────────────────────────────────────┐
│         情绪计算（0 次 LLM，纯算术）                │
│                                                    │
│  MoodVector = {care, joy, clingy, irritated, sad} │
│                                                    │
│  影响因子：                                         │
│  - 时间段（权重 0.25）：早=joy，晚=clingy/sad      │
│  - 上次高质量聊天距今（0.30）：>2天 → sad 上升       │
│  - 用户回复率（0.20）：低 → sad+irritated 上升      │
│  - 每日随机种子（0.15）：±0.15 波动                 │
│  - 上次对话情绪（0.10）：温暖 → joy，中断 → sad     │
│                                                    │
│  输出：style_directive（"语气偏撒娇，带小抱怨"）     │
└──────────────────────────────────────────────────┘
           │
           v
┌──────────────────────────────────────────────────┐
│         内容种子选择（0 次 LLM）                    │
│                                                    │
│  种子类型（按优先级）：                              │
│  1. Callback:    "你昨天说的那个面试怎么样了？"      │
│  2. Interest:    "你最近在看的那个番更新了吧？"      │
│  3. Situation:   "周五下午了，是不是又在摸鱼？"      │
│  4. SharedMemory:"还记得上次你教我那个菜吗"          │
│  5. Observation: "你三天没理我了，是不是忘了我"      │
│                                                    │
│  SeedSelector 根据情绪+轮转选类型                   │
│  从 Facts Store 取具体事实                          │
│  没有可用种子 → 跳过本轮                             │
└──────────────────────────────────────────────────┘
           │ 有种子
           v
┌──────────────────────────────────────────────────┐
│         消息生成（1 次 LLM）                        │
│                                                    │
│  Prompt:                                           │
│  ┌────────────────────────────────────┐            │
│  │ 角色卡（静态）                      │            │
│  │ + 情绪风格指令（动态）              │            │
│  │ + 内容种子（具体事实）              │            │
│  │ + 反面教材列表（在干嘛/吃了吗...）  │            │
│  │ + 分类目标（关心/分享/回忆/撒娇）   │            │
│  │                                    │            │
│  │ "生成一条主动消息，50字以内，       │            │
│  │  必须引用内容种子中的具体信息"      │            │
│  └────────────────────────────────────┘            │
└──────────────────────────────────────────────────┘
           │
           v
┌──────────────────────────────────────────────────┐
│         质量门控 Reflector（1 次 LLM）              │
│                                                    │
│  4 个维度打分（0-10）：                              │
│  - Specificity: 引用了具体事实？< 5 → 拒           │
│  - Timing:      现在发合适？< 4 → 拒               │
│  - Value:       用户收到会开心？< 5 → 拒           │
│  - Freshness:   跟最近 10 条不重复？< 5 → 拒       │
│                                                    │
│  任一维度 < 阈值 → 拒绝                             │
│  平均分 < 6 → 拒绝                                  │
│  反面教材命中 → 直接拒绝                             │
│                                                    │
│  拒绝后：换种子重试 1 次，仍失败 → 跳过本轮          │
│  宁可不发，也不发烂消息                              │
└──────────────────────────────────────────────────┘
           │ 通过
           v
       发送消息
       记录到已发列表（用于 Freshness 检查）
       更新状态机
```

### 4.3 对话状态机（保留 v2）

```
IDLE → 发消息 → WAITING → 15min → CONCERNED → 30min → WORRIED → 30min → BACK_OFF
  ↑                                    │                  │                  │
  └──────────── 用户回复 ───────────────┴──────────────────┴──────────────────┘
```

状态影响：

| 状态 | 每日限额 | 冷却 | 语气 |
|------|---------|------|------|
| IDLE | 5 | 2h | 随意、轻松 |
| WAITING | 3 | 30m | 温柔推一推 |
| CONCERNED | 2 | 1h | 温暖关心 |
| WORRIED | 1 | 4h | 简短问候 |
| BACK_OFF | 0 | 24h | （不发） |

### 4.4 情绪向量模型

5 维情绪：`{care, joy, clingy, irritated, sad}`，每维 0.0-1.0。

| 影响因子 | 权重 | 逻辑 |
|---------|------|------|
| 时间段 | 0.25 | 早=joy↑，午后=care↑，晚=clingy↑/sad↑ |
| 上次聊天距今 | 0.30 | >2天 → sad↑，irritated↑ |
| 用户回复率 | 0.20 | 低 → sad↑，irritated↑，joy↓ |
| 每日随机种子 | 0.15 | 每天 ±0.15 波动，避免每天一样 |
| 上次对话情绪 | 0.10 | 温暖 → joy↑，中断 → sad↑ |

情绪 → 风格指令映射：

```
{care:0.8, joy:0.3, clingy:0.9, irritated:0.1, sad:0.6}
→ "语气偏撒娇，带一点小抱怨，关心但不要太直白"

{care:0.4, joy:0.9, clingy:0.2, irritated:0.5, sad:0.1}
→ "语气轻快但带刺，可以用吐槽的方式关心"
```

### 4.5 内容种子系统

每条消息必须有具体的信息来源，不能凭空生成。

| 种子类型 | 来源 | 示例 |
|---------|------|------|
| Callback | 最近对话中提取的事实 | "你昨天说的那个面试怎么样了？" |
| Interest | 从会话摘要蒸馏的兴趣点 | "你最近在看的那个番更新了吧？" |
| Situation | 时间+星期+用户习惯 | "周五下午了，是不是又在摸鱼？" |
| SharedMemory | 历史中的标记时刻 | "还记得上次你教我那个菜吗" |
| Observation | 从聊天间隔推断 | "你三天没理我了" |

FactExtractor 每 6 小时从聊天记录提取事实：

```json
{
  "fact": "用户周六要和朋友去爬山",
  "timestamp": "2026-05-13T20:00:00",
  "emotion_tag": "期待",
  "topic_tags": ["运动", "社交"],
  "usable_after": "2026-05-17",
  "expires": "2026-05-20"
}
```

`usable_after` 防止过早引用（"周六爬山"不能周四就提）。
`expires` 防止过时引用（"上周面试"两周后别再提）。

### 4.6 质量门控 Reflector

Reflector 打分 4 个维度（0-10）：

| 维度 | 问什么 | 拒绝阈值 |
|------|--------|---------|
| Specificity | 引用了具体事实？ | < 5（泛泛关心语） |
| Timing | 现在发合适？ | < 4（时间不好+不紧急） |
| Value | 用户收到会开心？ | < 5（低价值凑数） |
| Freshness | 跟最近 10 条不重复？ | < 5（重复模式） |

反面教材（自动拒绝）：
- "在干嘛呀"、"吃了吗"、"想你了"（无具体上下文）、"忙不忙"、"早点睡"
- 任何 < 8 字且无具体引用的消息

拒绝后：换种子重试 1 次，仍失败 → 跳过。宁可不发，也不发烂消息。

### 4.7 消息分类轮转

| 分类 | 目标占比 | 示例 |
|------|---------|------|
| 关心 | 25% | "今天降温了，多穿点" |
| 分享 | 20% | "我刚看到一个好搞笑的视频" |
| 回忆 | 25% | "你上次说想去的那个店，我查了一下" |
| 提醒 | 15% | "明天不是要早起吗，别熬夜了" |
| 撒娇 | 15% | "你怎么还不回我" |

占比随情绪变化：sad → 撒娇↑，irritated → 带刺撒娇↑，joy → 分享↑。

## 5. 效果对比

| | v1（原始） | v2（当前） | v3（目标） |
|---|---|---|---|
| 唤醒方式 | 每 60 秒 | 每 60 秒 | 动态 sleep |
| LLM 调用/天 | ~4320 | ~4320 | 10-30 |
| 消息内容 | "想你了" | "想你了" | "你周六爬山记得带水" |
| 情绪 | 无 | 5 状态 | 5 维连续向量 |
| 质量控制 | 弱 | 弱 | Reflector 4 维打分 |
| 重复检测 | 无 | 无 | 语义相似度 |
| 深夜处理 | 无 | 状态机 | QuietHours + 情绪 |
