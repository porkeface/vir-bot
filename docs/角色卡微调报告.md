## 1. 任务目标

基于真实微信聊天记录，通过 QLoRA 微调 Qwen2.5-7B-Instruct 模型，使其学会「殴怡靖」的语言风格、性格特征和表达习惯，生成一个可加载的角色扮演 LoRA adapter。

## 8. 遇到的问题与修复

### 8.1 CUDA OOM（显存溢出）

**现象**：首次启动时 `torch.OutOfMemoryError: Tried to allocate 5.07 GiB`

**原因**：
- 之前的训练进程未正常退出，仍占用 7795 MiB 显存
- transformers 新版的 `caching_allocator_warmup` 尝试预分配显存

**修复**：
- `taskkill //F //PID` 杀死残留进程
- 添加 `low_cpu_mem_usage=True` 减少 CPU 内存占用

### 8.2 MemoryError（内存溢出）

**现象**：`datasets.map()` 预处理时 pickle 序列化失败

**原因**：`self._preprocess` 是 bound method，`datasets.map()` 会 pickle 整个 `LoRATrainer` 对象（包含 4.4B 模型权重）

**修复**：改用闭包函数，只捕获 `tokenizer` 和 `max_length` 两个轻量对象：

```python
def _preprocess_fn(examples):
    # 只引用 tokenizer 和 max_length，不引用 self
    ...
train_dataset = data.map(_preprocess_fn, batched=True, batch_size=256, num_proc=1)
```

### 8.3 LoggingCallback AttributeError

**现象**：`AttributeError: 'LoggingCallback' has no attribute 'on_init_end'`

**原因**：transformers 5.x 的 Trainer 调用了更多回调事件（`on_init_end`、`on_train_begin` 等），原 callback 只定义了 `on_log`

**修复**：添加 `__getattr__` 兜底，对所有未定义的 `on_*` 事件返回 no-op：

```python
def __getattr__(self, name):
    if name.startswith("on_"):
        return lambda *args, **kwargs: None
    raise AttributeError(...)
```

### 8.4 eval_strategy 参数名变更

**现象**：`TypeError: TrainingArguments.__init__() got an unexpected keyword argument 'evaluation_strategy'`

**原因**：transformers 5.8.1 将 `evaluation_strategy` 重命名为 `eval_strategy`

**修复**：`lora_config.py` 中改为 `"eval_strategy": "steps"`

### 8.5 bitsandbytes UnicodeDecodeError（无害）

**现象**：`UnicodeDecodeError: 'utf-8' codec can't decode byte 0xb2`

**原因**：bitsandbytes 在 Windows 上读取 CUDA 环境信息时的编码问题

**处理**：此错误发生在子线程中，不影响训练，可忽略

### 8.6 Windows 睡眠导致训练中断（首次尝试）

**现象**：首次训练在 step 72 时中断，step 时间从 60s 跳到 6506s

**原因**：Windows 自动睡眠，CUDA 上下文丢失

**修复**：训练前执行 `powercfg /change standby-timeout-ac 0` 禁用睡眠

### 10.2 已知的推理问题

首次部署时发现的问题（已修复）：

1. **流式输出阻塞事件循环**：`LoraProvider.chat_stream()` 中同步生成器阻塞 asyncio → 改用 `asyncio.to_thread()` 非流式调用
2. **模型输出乱码**：训练用 Alpaca 格式，推理用 Qwen chat template → 改用 `_build_alpaca_prompt()` 保持格式一致
3. **重复 emoji 刷屏**：`repetition_penalty` 太低 + `max_new_tokens` 太高 → 调整为 `penalty=1.4, max_tokens=150`

### 10.3 优化方向

- **数据质量**：筛选高质量对话样本，去除无意义的短回复（如 "?"、"="）
- **数据增强**：用 stage_a 蒸馏 prompt 生成更多样化的对话变体
- **多 epoch 训练**：如果 1 epoch 效果不够，可尝试 2-3 epoch（loss 曲线显示还有下降空间）
- **更大 rank**：当前 rank=32，可尝试 rank=64 提升表达能力（需更多显存或更小 batch）
- **合并 adapter**：将 LoRA 权重合并到基座模型，减少推理时的加载开销
- **换用 chat template 格式训练**：当前用 Alpaca 格式，推理时需要特殊处理；改用 Qwen chat template 格式训练可简化推理流程
