# vir-bot 性能优化方案

> 日期：2026-05-12
> 状态：待实施

## 问题分析

当前消息处理流程：

```
收到消息 → 意图分类(LLM) → 记忆检索 → 上下文构建 → AI生成回复(等待全部) → 一次性发送 → 记忆更新
```

主要瓶颈：
- AI 主回复生成：5-15秒（占总延迟 80%+）
- 意图分类 LLM 调用：1-3秒（短消息已跳过）
- 记忆检索：0.5-2秒
- 记忆更新：1-3秒（同步阻塞）

用户感知：发消息后等待 10-15 秒才收到回复，体验差。

## 优化方案

### 优化一：逐句 Streaming 输出（效果最显著）

**目标**：感知延迟从 10-15s 降到 2-3s

**方案**：
- 使用 `AIProvider.chat_stream()` 方法，AI 生成过程中逐句发送
- AI 回复天然是多行的（角色卡设定"用换行分隔每条消息"）
- 每生成完一句（遇到换行或句末标点）就立刻发送
- 长文本叙事时 AI 自然生成长段落，不会被强制拆分
- 不写死任何字数限制，完全由 AI 和上下文决定

**实现要点**：
- `MessagePipeline` 中调用 `chat_stream()` 替代 `chat()`
- 流式收集文本，遇到 `\n` 或句末标点时触发发送
- 发送通过 `PlatformAdapter.send_message()` 逐条投递
- 最后一句正常触发记忆更新

**预期效果**：
```
现在：  用户发消息 → [等待10秒] → 收到3条消息
优化后：用户发消息 → [等待2秒] → 收到第1条 → [1秒] → 第2条 → [1秒] → 第3条
```

### 优化二：记忆更新异步化

**目标**：AI 回复发出后不阻塞，记忆在后台更新

**方案**：
- AI 回复发送完成后，记忆更新任务放入 `asyncio.create_task()`
- 不等待记忆更新完成，立刻进入下一轮消息处理
- 用户感知不到记忆更新的延迟

**实现要点**：
- `MessagePipeline.process()` 末尾，记忆更新改为 fire-and-forget
- 需要处理好并发：同一用户的记忆更新不能冲突
- 失败时记录日志，不影响正常流程

### 优化三：上下文构建并行化

**目标**：意图分类和记忆检索并行执行

**方案**：
- 短消息（<15字）：已跳过 LLM 分类，直接走规则（已完成）
- 长消息：意图分类和记忆检索同时发起，`asyncio.gather()` 等待
- 记忆检索不依赖分类结果（多路并行检索已实现）

**实现要点**：
- `RetrievalRouter.retrieve_for_context()` 中，分类和检索并行
- 分类结果只用于格式化提示，不阻塞检索

## 实施顺序

1. **优化一**（Streaming）- 效果最明显，优先实施
2. **优化二**（异步记忆）- 锦上添花
3. **优化三**（并行上下文）- 锦上添花

## 设计原则

- **不写死规则**：消息拆分由 AI 决定，不硬编码字数限制
- **自然体验**：像真人发微信，不是机械地逐字输出
- **角色卡驱动**：所有行为从角色卡读取，不硬编码在代码里
- **渐进式优化**：每项优化独立，可单独启用/禁用
